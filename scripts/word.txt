## Adding OpenAPI to an Elysia app
1. **Install the plugin**  \n   ```bash\n   npm i @elysiajs/openapi\n   ```
2. **Import and use it** – put the middleware **before** you define routes so it can scan them.
   ```ts\n   import { Elysia, t } from 'elysia'\n   import { openapi } from '@elysiajs/openapi'
   const app = new Elysia()\n     // ① add OpenAPI support\n     .use(openapi())                // default endpoint = /openapi.json + UI at /docs\n     // ② define a typed route (type info is what OpenAPI reads)\n     .get(\n       '/user/:id',\n       ({ params: { id } }) => ({ id }),\n       {\n         params: t.Object({ id: t.Number() }),\n         response: t.Object({ id: t.Number() })\n       }\n     )\n     .listen(3000)
   console.log('🦊 Elysia running at http://localhost:3000')\n   ```
3. **Visit the docs**  \n   * OpenAPI JSON: `http://localhost:3000/openapi.json`  \n   * Swagger UI: `http://localhost:3000/docs`
### Customising the endpoint (optional)
```ts\n.use(openapi({ path: '/api-spec', documentation: { info: { title: 'My API', version: '1.0.0' } } }))\n```
* `path` changes the JSON endpoint (`/api-spec`).  \n* `documentation.info` lets you set title, version, description, etc.
### Why it works
* The `openapi` plugin walks through every route **after** it’s registered.  \n* It reads the **type definitions** you supplied (`t.Object`, `t.Number`, …).  \n* Those types become the **schemas** in the generated OpenAPI spec, so the docs stay in sync automatically.

**Quick cheat‑sheet**
| Step | Code | What it does |\n|------|------|--------------|\n| Install | `npm i @elysiajs/openapi` | Adds the plugin |\n| Import | `import { openapi } from '@elysiajs/openapi'` | Bring plugin into scope |\n| Use | `.use(openapi())` | Enables auto‑generated spec |\n| Define typed routes | `.get('/path', handler, { params: t.Object(...), response: t.Object(...) })` | Gives OpenAPI the schema |\n| Run | `.listen(3000)` | Starts server |\n| Docs | `/openapi.json` & `/docs` | View spec & UI |
